# PR #18025 — What It Does (Understanding)

## One Line

UIBundle (your React app) is now linked to a CustomApplication (TabSet) via a junction entity, giving it profile/permission set visibility through the existing App Manager infrastructure.

## The Problem It Solves

UIBundle was just raw UI code with no concept of "who can see this app." Salesforce already has that concept — it's called CustomApplication (internally stored as a TabSet entity). Lightning apps, Service Console — all TabSets. They already support profile visibility, permission sets, App Launcher items.

So instead of building access control from scratch, we hook UIBundle into the existing system.

## What Gets Created When You Deploy App "xyz"

You deploy two metadata files:

```xml
<!-- uiBundles/xyz/xyz.uiBundle-meta.xml -->
<UIBundle>
  <target>Lightning</target>
</UIBundle>

<!-- applications/xyz.app-meta.xml -->
<CustomApplication>
  <label>xyz</label>
  <webApplication>xyz</webApplication>
</CustomApplication>
```

On deploy, this happens:

1. UIBundle entity is created with `target=Lightning`
2. CustomApplication sees `webApplication=xyz` → sets its `TabType=UI_BUNDLE` (dbValue 319)
3. A junction record (`UIBundleApplication`) is created linking the two
4. App Launcher picks up the TabSet → shows it to users with profile/permset access
5. The App Launcher URL is generated by traversing junction → UIBundle → `/lwr/application/ai/{ns}-{name}`

## The Junction Entity (UIBundleApplication)

```
UIBundle ←──FK──  UIBundleApplication  ──FK──→ TabSet (CustomApplication)
```

- 1:1 relationship (unique indexes on both FKs)
- Cascade delete on both sides
- Created during `CustomApplication.upsertWebApplicationLink()`
- Read during `TabSetSwitcherAppInfo.getUIBundleUrl()` and `CustomApplication.hook_readFromEntityObject()`

## The `target` Field on UIBundle

| Value | What happens |
|-------|-------------|
| `AppLauncher` (default) | UIBundle creates its own AppMenuItem. Open access. Old behavior. |
| `Experience` | Linked to Digital Experience Site. Access via Network/Site. |
| `Lightning` (new) | Linked to CustomApplication. No self-created AppMenuItem. Access via TabSet profile visibility. |

## What This PR Blocks in App Manager

Multi-framework (UI_BUNDLE) apps cannot be:
- Edited (managed by vibes/skill, not App Manager)
- Cloned
- Deleted (must delete the UIBundle, cascade handles the rest)
- Managed

## What This PR Does NOT Do

- **No runtime enforcement** — if someone hits `/lwr/application/ai/c-xyz` directly, LWR still serves it
- The App Launcher just hides the link from unauthorized users, it doesn't lock the door
- The URL generated still points to the same LWR path with no access check in front of it

## File-by-File

| File | Role |
|------|------|
| `UIBundleApplication.entity.xml` | New junction entity definition |
| `CustomApplication.java` | `webApplication` field, junction create/read, block delete for UI_BUNDLE |
| `UIBundleObject.java` | Only creates AppMenuItem for `AppLauncher` target, not `Lightning` |
| `UIBundle.java` (metadata-impl) | Removes old AppMenuItem creation code, adds `Lightning` to valid targets |
| `TabSetSwitcherAppInfo.java` | URL generation: junction → UIBundle → WebApplicationUrlConverter |
| `AppMenuItem*Action.java` | Blocks edit/clone/delete/manage for Multi-framework type |
| `ConfigurationBuilder.java` | WebApplication registration moved before CustomApplication (dependency order) |
| `udd-tabsets.xml` | Registers `UiBundle` TabSet type (319) |
| `SfdcModuleType/sfdcsetupnames/tooling.xml` | Labels and registration |
